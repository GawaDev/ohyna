# 06. セキュリティ

## 1. 脅威モデル

本製品は **サーバに展開し、一般利用者がブラウザから利用する**前提です。  
認証・TLS・レート制限はアプリ内ではなく、**前段のリバースプロキシ／IdP** で担保します。

| 前提 | 内容 |
|------|------|
| 配置 | アプリはプロキシ背後。開発時既定バインドは `127.0.0.1` |
| 利用者 | 一般公開（認証済みセッションを想定）。入力 Markdown は利用者ごとに信頼境界が異なる |
| 非対応 | 生の Python HTTP をインターネットへ直接公開すること、CORS `*` |

アプリ本体には利用者認証がありません。公開面では必ずプロキシ認証（Basic／OIDC／SSO 等）を付けてください。

## 2. デプロイ構成（必須）

```text
[利用者ブラウザ]
       | HTTPS
[リバースプロキシ]  … TLS、認証、レート制限、リクエストサイズ上限、ログ
       | HTTP (内部)
[ohyna serve]  … 127.0.0.1 またはプライベート網のみ
```

| 項目 | 推奨 |
|------|------|
| TLS | プロキシで終端 |
| 認証 | プロキシ／IdP（未認証アクセスをアプリへ渡さない） |
| レート制限 | `/preview`・`/pdf`・`/analyze` を厳しめに |
| ボディ上限 | プロキシ側でも制限（アプリは 8 MiB） |
| CORS | 同一オリジンが基本。別オリジンが必要なら `OHYNA_ALLOWED_ORIGINS` |
| プロセス公開 | `serve` をインターネットに直接バインドしない |

非 loopback にバインドすると、前段防護を忘れないよう警告を出します。

## 3. 主なリスクと緩和

| リスク | 緩和 |
|--------|------|
| 未認証 API の悪用・コスト攻撃 | プロキシ認証＋レート制限。PDF／図描画は重い |
| プレビュー XSS → 親オリジン脱出 | iframe `sandbox="allow-scripts"` のみ（`allow-same-origin` なし）、本文 bleach、Mermaid は個別描画 |
| PDF 経路の SSRF / 任意ファイル読取 | Playwright のネットワークを allowlist に制限。利用者指定の `file:` URL は拒否 |
| サーバ FS の探索 | パスは `ensure_under` でルート配下に拘束 |
| Zip Slip / パストラバーサル | `ensure_under` で gui・docs・メディア・`styleFile` を拘束 |
| 巨大ボディ DoS | リクエスト上限 8 MiB（＋プロキシ側上限） |
| CSS 注入 | `fontFamily` / `fontSize` / `lineHeight` を正規表現で制限（`url(` や `;` 等を拒否） |
| 図内 HTML | Mermaid `htmlLabels: false` 等。PDF 埋め込み前にサニタイズ済み HTML へ載せる |

## 4. HTML サニタイズ（bleach）

**利用者由来**の Markdown 変換後 HTML 断片は bleach を通します。Mermaid／KaTeX など製品レンダラが生成した HTML／SVG は Trusted 出力として、サニタイズ**後**に差し込みます（最終 HTML 全体に同じ bleach をかけない）。

**許可タグ（実装 `_ALLOWED_HTML_TAGS` と同一）**  
`a`, `abbr`, `b`, `blockquote`, `br`, `caption`, `code`, `col`, `colgroup`, `dd`, `del`, `details`, `div`, `dl`, `dt`, `em`, `h1`, `h2`, `h3`, `h4`, `h5`, `h6`, `hr`, `i`, `img`, `input`, `ins`, `kbd`, `li`, `mark`, `ol`, `p`, `pre`, `q`, `s`, `section`, `span`, `strong`, `sub`, `summary`, `sup`, `table`, `tbody`, `td`, `tfoot`, `th`, `thead`, `tr`, `ul`

**属性**

| 対象 | 属性 |
|------|------|
| `*` | `class`, `id`, `title`, `role`, `aria-label` |
| `a` | `href`, `title`, `rel` |
| `img` | `src`, `alt`, `title`, `width`, `height` |
| `input` | `type`, `checked`, `disabled` |
| `details` | `open` |
| `td` | `colspan`, `rowspan` |
| `th` | `colspan`, `rowspan`, `scope` |
| `col` / `colgroup` | `span` |

**URL 再フィルタ**

| 属性 | 残すスキーム |
|------|----------------|
| `href` | `http` / `https` / `mailto` / `#` / `/` で始まるパス |
| `src` | `http` / `https` / `data:image/` /（内部処理用の）`file:` |

`javascript:` などは除去されます。

## 5. Playwright ネットワーク許可

PDF 化・サーバ側 Mermaid／KaTeX 検証で外向きに許すもの:

| 許可 | 用途 |
|------|------|
| `fonts.googleapis.com` / `fonts.gstatic.com` | Web フォント |
| KaTeX の jsDelivr CDN | 数式 |
| Mermaid 系 jsDelivr CDN | 図描画 |
| `data:` | 埋め込み画像など |
| 許可ルート配下の `file:` | ローカル画像（CLI ファイル経路） |
| 自前の about / 仮想 origin ページ | 描画ホスト |

上記以外へのリクエストは中断します。サーバが外向き HTTPS を必要とするため、ファイアウォールで CDN／フォント宛を許可してください（オフライン専用にする場合は同梱方針を別途設計する）。

## 6. パス拘束

| 対象 | 規則 |
|------|------|
| `/gui/*` | `gui/` 配下。`..` 拒否 |
| `/docs/*` | カタログ掲載ファイルのみ |
| `/covers/<style>/<pattern>` | `themes/covers/` 配下の画像のみ |
| CLI のテーマ CSS・作業ディレクトリ | ルート配下への拘束（`ensure_under`） |

## 7. 運用上の注意

1. 一般公開面では、プロキシ認証を必須にする
2. GUI 経由の PDF では相対ローカル画像は埋め込まない（意図的。サーバ FS 露出を抑える）
3. 許可タグやネットワーク allowlist を広げる変更は、本ドキュメントと実装を同時に更新する
4. マルチテナントで文書をサーバ保存する場合は、本リポジトリ外のストレージ設計（隔離・暗号化・保持期間）が別途必要
