# 01. アーキテクチャ

## 1. リポジトリ構成

```
ohyna/
  requirements.txt
  README.md
  ohyna/                 # Python パッケージ（変換・解析・HTTP・CLI）
  styles/                # 色テーマ JSON（16 種）
  themes/
    blue-print.css       # 印刷・プレビュー共通 CSS
    covers/              # 表紙 WebP（style × pattern）
  web/                   # GUI ソース
  gui/                   # web のビルド成果物（サーバが配信）
  docs/                  # 本仕様
```

## 2. モジュール責任

| モジュール | 責任 |
|-----------|------|
| `cli.py` | コマンドライン入口（`render` / `pdf` / `serve`） |
| `server.py` | HTTP API と `gui/`・`docs/` の配信 |
| `frontmatter.py` | YAML front matter（`ohyna:`） |
| `design.py` | フォント・角丸・表紙パターン・CSS 変数 |
| `pdf.py` | Markdown→HTML 断片、サニタイズ、プレビュー HTML、PDF 化 |
| `analyze.py` | 静的解析（設定・構造・Pygments・Mermaid・KaTeX） |
| `engine.py` | Mermaid→SVG の公開入口とキャッシュ |
| `mermaid_js.py` | Playwright 上の Mermaid.js 描画 |
| `katex_js.py` | KaTeX CDN 定数 |
| `style.py` | 図テーマ（`styles/*.json`）の読込 |
| `theme.py` | 印刷用 CSS の合成 |
| `cover_assets.py` | 表紙画像の data URI 化 |
| `paths.py` | ルート配下へのパス拘束 |

GUI（`web/src/`）は編集・プレビュー iframe・PDF モーダル・文書設定 UI を担当し、変換本体は常にサーバ API に委譲します。配信は `serve`（ブラウザ／PWA）です。

## 3. データフロー

### 3.1 編集 → プレビュー

```
Markdown 編集
  →（480ms debounce）
  → POST /analyze
  → error が 0 件なら POST /preview
  → markdown_to_preview_html
       ・FM 解決・本文変換・bleach
       ・Mermaid はクライアント描画用プレースホルダ
  → GUI iframe で A4 用紙分割＋Mermaid/KaTeX CDN 描画
```

静的解析に error がある間は `/preview` を呼びません。直前に成功したプレビュー HTML があればそれを保持し、状態は「未更新」になります。

### 3.2 PDF 生成・確認

```
PDF生成（ヘッダボタン）
  → 最新 Markdown で /analyze（再検証）
  → error 0 件なら POST /pdf
  → markdown_to_pdf
       ・各 ```mermaid を render_flowchart_svg（Playwright）
       ・KaTeX を HTML に埋め込み
       ・html_to_pdf（Chromium page.pdf）
  → 生成完了後に確認モーダル（react-pdf）を開く → PDFを保存
```

サーバ側の `/preview` と `/pdf` も、処理前に同じ静的解析を行い、error があれば **HTTP 422** で拒否します。

### 3.3 Mermaid 描画の分岐

| 経路 | 実行場所 | 出力 |
|------|----------|------|
| プレビュー | 利用者ブラウザ（CDN Mermaid） | 画面上の SVG |
| PDF / CLI 図 | サーバ Playwright | 埋め込み SVG |

どちらも公式 Mermaid.js を使い、描画後に SVG 余白を切り落として用紙幅へ合わせます。

## 4. 公開 Python API

`ohyna` パッケージから利用できる主な入口:

- `ohyna` / `markdown_to_preview_html` / `markdown_to_html_fragment`
- `markdown_file_to_pdf` / `markdown_to_pdf` / `html_to_pdf`
- `parse_document` / `parse_frontmatter` / `extract_ohyna_config` / `merge_frontmatter`
- `render_flowchart_svg` / `list_presets` / `DiagramStyle` / `MarkdownOptions`

完全な一覧は `ohyna.__all__` を参照してください。

## 5. プレビューと PDF の位置づけ

| | プレビュー | PDF |
|--|-----------|-----|
| 目的 | 編集中の素早い確認 | 配布・印刷の最終成果物 |
| ページ分割 | iframe 内 JS による A4 近似 | Chromium の CSS 印刷 |
| Mermaid | クライアント描画 | サーバ埋め込み SVG |
| ゲート | 静的解析通過が必要 | 同左（HTTP） |

体裁の最終判断は常に PDF 側で行ってください。

## 6. GUI メッセージコンソール（表示契約）

GUI 下部は IDE のパネルに相当します。編集領域と垂直 Splitter で高さを変えられ、別ウィンドウへ外だしできます。常時チップで検査・プレビュー状態を示し、展開すると「問題」「出力」タブになります。上部中央トーストとの振り分け契約も含みます。実装は `web/src/messageConsoleStore.ts` / `MessageConsole.tsx` / `consolePopoutBridge.ts` / `PopoutConsole.tsx` / `notify.tsx` / `diagFormat.ts` です。

### 6.0 状態チップ（バー常時表示）

ペインヘッドには出しません。下部バーに集約します。

| チップ | 見え方 | 備考 |
|--------|--------|------|
| 検査 | アイコン＋`Markdown`（✔／✖／⚠／読込中） | クリックで「問題」タブ。詳細はツールチップ。問題なしをログに連打しない |
| プレビュー | アイコン＋`プレビュー`（✔最新／⚠未更新／✖エラー／読込中／待機） | 詳細はツールチップ |

### 6.1 「出力」エントリの項目

| 項目 | 型 | 画面上の見え方 |
|------|-----|----------------|
| `id` | string | 非表示。解析ゲートは固定 id `ohyna-analysis` で差し替え更新 |
| `level` | `error` / `warning` / `info` / `success` | 区分ラベル **エラー** / **注意** / **情報** / **完了**（アイコン付き） |
| `title` | string | 各行の見出し。折りたたみバーでも先頭に表示 |
| `detail` | string（任意・複数行可） | 見出しの下に等幅で表示。折りたたみ時は先頭行だけを `title — …` で添える |
| `at` | Unix ミリ秒 | 右端に `HH:mm:ss` |

「出力」が空のときはバーに「メッセージなし」。消去ボタンは出力履歴だけ削除します（状態チップは残る）。件数バッジは出力のエラー（赤）と注意（橙）です。

### 6.2 行位置の表記

ドキュメント内の行を指すときは必ず **「N行目」** とする（「N行:」は使わない）。

| 用途 | 書式例 |
|------|--------|
| 問題一覧・コンソール詳細の 1 行 | `12行目: タイトルは必須です` |
| 短い要約（通知・ブロック理由） | `問題 2 件: 12行目 タイトルは必須です（ほか 1 件）` |
| アクセシブルネーム | `12行目、タイトルは必須です。クリックで移動` |

### 6.3 トーストとの関係

| 区分 | トースト | コンソール |
|------|----------|------------|
| エラー・注意 | 見出し＋「詳細は下部の出力を確認してください」（詳細本文は載せない） | `title` と `detail`（詳細全文） |
| 情報・完了 | 見出し＋短い本文 | 同じ内容を履歴として残す |

`notify({ toConsole: false })` のときだけコンソールへ書きません。新しい操作エラー（解析の差し替え id 以外）が来るとコンソールを自動で開きます。

ドキュメント設定の不足で保存や **PDFを作成** が止められたときも、設定モーダルは開かずコンソールへ出します（「PDFを作成」は IDE のデバッグ実行に相当）。

### 6.4 解析ゲート時の表示例

プレビューを止めているあいだ、コンソールには次のような 1 エントリが載ります。

- **区分**: エラー  
- **見出し**: `問題 3 件のためプレビューを更新できません`  
- **詳細**（改行区切り）:
  ```
  12行目: タイトルは必須です
  86行目: KaTeX 構文エラー: …
  ```
