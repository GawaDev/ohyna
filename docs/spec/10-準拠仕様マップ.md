# 10. 準拠仕様マップ

版: **1.0.0**  

本文書は、**製品契約（Ohyna Markdown）と外部仕様／参照実装の境界**、および**競合時の解決規則**を定義します。画面ヘルプ内で自己完結します。

読み方:

| 区分 | 意味 |
|------|------|
| **製品契約** | 利用者が従う入力・意味・ゲート。基準は主に [08](./08-入力解読仕様.md)・[09](./09-出力仕様.md)・[03](./03-文書設定リファレンス.md) |
| **採用仕様** | 外部規格をそのまま参照（再定義しない） |
| **制限付き採用** | 外部エンジンの解釈範囲を製品が受理する部分集合として固定 |
| **参照実装** | 現バージョンのライブラリ名・版。交換しても製品契約は維持できる |
| **実装ピン** | 再現性のため版または CDN タグを固定しているもの |

---

## 0. 製品言語の位置づけ

Ohyna は文書形式 **Ohyna Markdown 1.0** を定義します。

- 利用者契約の主語は「Ohyna Markdown で使える記法」です。
- 構文の基礎に Markdown 系の慣例を用い、図・数式・設定・PDF 組版を製品側で定義します。
- 表・タスクリストなど一般的な記法の一部は **記法互換** として提供します。表示結果は本製品の出力仕様に従います。

```text
利用者契約:     Ohyna Markdown 1.0 ＋ Ohyna Rendering
採用規格:       JSON (ECMA-404)、ISO 216 A4 など
制限付き採用:   固定版 Mermaid / KaTeX が解釈する本文
参照実装:       Markdown 変換・ハイライト・印刷エンジン等
```

## 1. 競合時の優先順位

同一入力または出力について複数の仕様・実装が異なる結果を示す場合、次の順序で解決します。

1. **セキュリティ契約**（本章 §8）
2. **Ohyna の明示的な製品契約**（Ohyna Markdown / Rendering / 本マップの基準表）
3. **Rendering Profile で固定された外部仕様**（版ピン付き）
4. **固定されたライブラリの実装挙動**（参照実装）
5. **参考として記載した CommonMark、GFM その他**

CommonMark および GFM は、明示的に準拠すると記載した範囲を除き、互換性判断の参考であり、製品契約を上書きしません。

例えば GFM で許容される HTML でも、製品のサニタイズ規則で削除するならセキュリティ契約を優先します。

### 1.1 処理ごとの基準

| 対象 | 基準 |
|------|------|
| フェンス認識 | **Ohyna Fence Grammar**（[08](./08-入力解読仕様.md) §3） |
| 通常 Markdown 本文変換 | 製品が受理する構文（固定拡張セット） |
| 言語識別子の可否 | **Ohyna Language Registry** |
| Mermaid フェンスの種別 | 製品契約（図 / `code` / 不明モード） |
| Mermaid 本文構文 | Rendering Profile の Mermaid |
| 数式区切り・数式フェンス | 製品契約 |
| 数式本文 | Rendering Profile の KaTeX |
| 設定の意味・マージ | Document Settings（[03](./03-文書設定リファレンス.md)） |
| HTML 許可範囲 | 本章 §8（利用者由来断片） |
| エンジン生成 HTML/SVG | 製品の Trusted 出力（専用経路） |
| 最終ページ割・用紙箱 | CSS `@page` ＋ 印刷エンジン |
| プレビュー分割 | 製品独自の近似。正式出力ではない |
| 静的解析ゲート | 製品契約（画面のプレビュー／PDF は error があると進まない） |

エンジンフェンスおよび静的解析対象フェンスの認識には Ohyna Fence Grammar を使用します。一般的な Markdown 処理系と差がある場合、**Ohyna Fence Grammar の判定を優先**します。

## 3. Markdown 本文（Ohyna Markdown）

### 3.1 契約と参照実装

- **製品が受理する構文**が利用者契約です。
- 表・タスクリスト・自動リンク等は **GFM 由来の記法互換**であり、出力互換・表示互換は保証しません。
- HTML ブロック内の Markdown（`md_in_html`）は**無効**です。

### 3.2 製品が独自に決めるもの

| 項目 | 契約 |
|------|------|
| エンジン用フェンスの退避 | 図・数式を変換前にプレースホルダ化。`mermaid code` は言語識別子へ正規化 |
| `<kbd>` | 許可 HTML として残す |
| details／タスクチェック | 出力時は常に展開・操作不可 |
| 見出し keep-next | [09](./09-出力仕様.md) §5 |

## 8. HTML・セキュリティ（信頼境界）

画面から使うときの信頼境界の要約です（運用担当向けの詳細なデプロイ手順は本ヘルプの対象外です）。

| 起源 | 扱い |
|------|------|
| 利用者 HTML／Markdown 由来断片 | 許可リストでサニタイズ → URL 再フィルタ |
| Mermaid／KaTeX 等の製品レンダラ出力 | Trusted。サニタイズ後に差し込み |
| 最終文書 | 外部通信は許可された宛先のみ。ローカルファイル探索を抑止 |

「最終 HTML 全部に同じサニタイズをかける」ことはしません。

### 8.1 利用者由来 HTML の許可（要約）

許可タグの例: 見出し・段落・リスト・表・リンク・画像・コード・引用・`<details>`・`<kbd>` など、文書に必要なもの。  
`javascript:` などの危険な URL は除去されます。リンクは `http` / `https` / `mailto` / `#` / `/` で始まるパスなど、製品が許すスキームのみ残します。画像 `src` は `http` / `https` / `data:image/` など。

### 8.2 CSS 注入対策

`fontFamily` / `fontSize` / `lineHeight` は正規表現で受理範囲を制限します（`url(` や `;` など危険な断片を拒否）。

### 8.3 PDF 化時の外部通信（要約）

許可しうるもの: Web フォント、数式／図描画用の製品指定 CDN、`data:`、製品内部の描画ホスト。それ以外は遮断します。

### 8.4 本画面での画像

本画面から PDF 化するとき、ドキュメントからの相対パスによるローカル画像は埋め込みません（サーバ上のファイルを不用意に読まないため）。`https:` 等で参照できる画像を使ってください。
